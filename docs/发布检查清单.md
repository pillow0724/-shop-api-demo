# 发布检查清单

发布（发版）前必须逐项确认，任何一项不满足都不能发布。

## 一、代码与评审

| 检查项 | 要求 |
|---|---|
| PR 状态 | 相关改动已合入 `main`，无未合并的发布分支 |
| 评审 | 至少 1 名 Owner approve |
| 变更说明 | 有 changelog，写清影响面与回滚方式 |

## 二、质量门禁

| 检查项 | 要求 |
|---|---|
| CI | **全绿**（`ci` workflow 必须 success，不能有 failure） |
| 单元测试 | 通过率 100%，不允许 skip 关键用例 |
| 覆盖率 | 新增代码覆盖率不低于 60% |

## 三、风险与阻塞

| 检查项 | 要求 |
|---|---|
| Issue | 无 **P0 / P1** 未解决 Issue |
| 安全 | 涉及 `AuthFilter` 等鉴权改动的，必须由安全同学**复核**并留结论 |
| 依赖 | 无高危 CVE |

## 四、发布动作

1. 打 tag（`vX.Y.Z`）并记录 commit SHA；
2. 灰度 1 台，观察 30 分钟错误率与延迟；
3. 全量发布；
4. 保留回滚包。
